APPOINTMENT SCHEDULING SYSTEM
DAY 1 — DEVELOPMENT SUMMARY
Date: 26 October 2026

============================================================
1. PROJECT OVERVIEW
============================================================

I worked on the foundation of a clinic/appointment scheduling application.

The system is being developed with a React + TypeScript frontend and an Express + TypeScript backend, using MongoDB/Mongoose for data storage. The frontend uses React Router for navigation, Redux Toolkit for authentication state, Axios for API requests, and Tailwind CSS with Lucide icons for the UI.

The intended roles discussed so far are:
- Patient
- Doctor
- Admin

============================================================
2. AUTHENTICATION BACKEND
============================================================

Registration controller:
- Accepts name, email, password, and phone.
- Validates required fields and minimum name/password lengths.
- Normalizes the name and email.
- Checks whether an account with the email already exists.
- Hashes the password with bcrypt.
- Creates a User with role "patient", authProvider "local", and isVerified true.
- Creates a corresponding Patient record linked to the User.
- Removes the newly created User if Patient record creation fails.
- Generates a JWT and returns it along with the user details.
- Handles duplicate-email errors and unexpected registration errors.

Login controller:
- Validates that email and password are strings.
- Finds the user by normalized email and selects passwordHash.
- Checks local authentication and verifies the password.
- Supports an optional expected role for doctor/admin login portals.
- Generates a JWT and returns the token and basic user details.

JWT:
- The token generator uses JWT_SECRET and signs a userId claim.
- The configured token expiry is seven days.

============================================================
3. AUTHENTICATION MIDDLEWARE AND SESSION RESTORATION
============================================================

The protectedRoute middleware:
- Reads the Authorization header.
- Requires a Bearer token.
- Verifies the JWT using JWT_SECRET.
- Checks the decoded userId.
- Finds the corresponding User in MongoDB.
- Must assign the user to req.user before calling next().

The /auth/me endpoint uses req.user to return the authenticated user's information.

Frontend session restoration:
- App.tsx requests /auth/me when the application starts.
- It restores the authenticated user into Redux if the request succeeds.
- It clears the user state if authentication fails.
- Protected routes redirect unauthenticated users to /login.
- Role-based dashboard routes are configured for patient, doctor, and admin access.

Axios configuration:
- The shared Axios instance uses VITE_BACKEND_URL as its base URL.
- withCredentials is enabled.
- A request interceptor reads localStorage key "token" and sends:
    Authorization: Bearer <token>
